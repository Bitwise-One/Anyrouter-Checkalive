### 关键技术结论（Codex CLI，实测版本 0.162.0）
- config.toml 结构：`model` + `model_provider` + `preferred_auth_method="apikey"` + `forced_login_method="api"` + `[model_providers.<id>]`（含 `base_url` / `env_key` / `wire_api`）。token 通过 `env_key` 指向的环境变量（本项目用 `ANYROUTER_TOKEN`）传入，不落盘。
- `codex exec` 本身非交互、从不弹审批；**没有** `-a`/`--ask-for-approval` 参数（这是网上旧文档的坑，实测 0.162.0 会报 `unexpected argument '-a' found`）。
- 有效 flag：`-m`、`-s read-only`、`--skip-git-repo-check`（还有 `--json`、`-o`、`--ephemeral` 等）。
- `--full-auto` 已废弃。
- 调用：`ANYROUTER_TOKEN="$TOKEN" timeout 120 codex exec -m "$MODEL" -s read-only --skip-git-repo-check "$PROMPT"`。

### 经验教训（Windows 本地测试坑）
- Git Bash 下 `mktemp`（无模板）返回 `C:\...` 混合路径，塞进 `PATH` 后无法按 POSIX 规则命中 mock 命令；用 `/tmp/xxx` 这样的 POSIX 路径建 mock 目录才有效。
- 该环境的沙箱有 safe-delete 包装器，`rm -f` 作用于 `C:\` 前缀路径会报 `SAFE_DELETE_INVALID_PATH` 并返回非零，`set -e` 会让脚本提前退出。已在 keepalive.sh 的清理步骤加 `|| true` 兜底（清理不应影响成败判定）。
